System Design Blueprint · Version 1.0

Asset Management
untuk HRIS Cahaya Optima Karya

Rancangan bisnis dan teknis untuk mengelola seluruh siklus hidup aset: registrasi, penyerahan, transfer, pengembalian, perawatan, stock opname, hingga disposal.

Keputusan desain utama
Aset adalah identitas permanen. Pemegang, lokasi, kondisi, dan status berubah melalui transaksi historis yang dapat diaudit—bukan dengan menimpa data lama.

Assignment dan transaksi lama tidak ditimpa atau dihapus.

03 · Lifecycle

Status Lifecycle dan Kondisi

Status menjawab “aset sedang berada pada proses apa?”, sedangkan kondisi menjawab “keadaan fisiknya bagaimana?”. Keduanya tidak boleh disatukan.

Draft→ Available→ Assigned→ Maintenance→ Available
Assigned→ Lost→ Ditemukan→ Inspeksi→ Available
Available→ Retired→ Disposed
StatusArtiAksi yang diperbolehkan
draftRegistrasi belum finalEdit, lengkapi, aktivasi
availableSiap digunakanAssign, transfer lokasi, maintenance, retire
assignedMemiliki assignment aktifReturn, transfer custodian, lapor rusak/hilang
maintenanceDalam servis/perawatanSelesaikan maintenance; tidak dapat di-assign
lostBelum ditemukanInvestigasi atau ditemukan kembali
retiredTidak dipakai, masih tercatatDisposal setelah approval
disposedLifecycle selesaiRead-only

Kondisi: newgoodfairdamagedunusable

Invariant: status assigned tidak boleh ada tanpa satu assignment terbuka; satu aset tidak boleh mempunyai dua assignment terbuka.
04 · Workflow

Flow Registrasi dan Penyerahan

A. Registrasi aset

Input master→ Validasi kode & serial→ Simpan dokumen privat→ Available
Asset OfficerMengisi kategori, identitas, lokasi, nilai perolehan, garansi, kondisi, foto, dan dokumen.
SistemMembuat kode bila otomatis, memvalidasi uniqueness, menyimpan dokumen privat, mencatat audit, dan menetapkan status awal.

B. Penyerahan kepada karyawan

Pilih aset→ Available?→ Karyawan aktif & dalam scope?→ Konfirmasi kondisi→ Assignment aktif
Data wajibValidasi kritisEfek berhasil
Aset, karyawan, tanggal, kondisi, tujuan, petugas; target return bila sementara. Aset tersedia; employee aktif; object berada dalam scope; tidak ada assignment terbuka. Buat assignment; ubah status; tulis transaction; audit; kirim notifikasi; opsional berita acara.
Concurrency: workflow harus melakukan lockForUpdate() pada aset di dalam DB::transaction(). Dua petugas tidak boleh berhasil menyerahkan aset yang sama secara bersamaan.
05 · Workflow

Flow Pengembalian dan Transfer

A. Pengembalian

Cari assignment aktif→ Inspeksi & foto→ Kondisi?→ Available / Maintenance / Lost
Hasil inspeksiStatus berikutTindak lanjut
Baik dan lengkapavailableSiap untuk assignment berikutnya
Perlu servismaintenanceBuat maintenance case
Rusak beratretiredReview kelayakan dan disposal
Tidak dikembalikan/hilanglostInvestigation record dan notifikasi

B. Transfer

Assignment lama→ Tutup & catat kondisi→ Validasi tujuan→ Buat assignment/lokasi baru→ Transfer selesai

Transfer dibedakan menjadi: antarkaryawan, antardivisi, antarcabang, dan ke lokasi/gudang. Penutupan dan pembukaan assignment harus berhasil atau gagal sebagai satu unit transaksi.

Dilarang: mengubah langsung employee_id atau branch_id tanpa transaction record. Cara tersebut menghilangkan jejak asal aset.
06 · Workflow

Maintenance, Stock Opname, dan Offboarding

Maintenance

Keluhan / jadwal→ Check-in servis→ Vendor / internal→ Biaya & tindakan→ Selesai & inspeksi

Case menyimpan keluhan, vendor, tanggal, kondisi, biaya, komponen, dokumen servis, petugas, serta jadwal berikutnya. Selama case aktif, aset tidak dapat di-assign.

Stock opname

Buka periode→ Scan / cari aset→ Cocok?→ Review selisih→ Rekonsiliasi

Hasil scan disimpan sebagai temuan. Master tidak berubah sebelum reviewer menyetujui rekonsiliasi.

Offboarding karyawan

Proses keluar→ Ada aset aktif?→ Tahan / warning→ Return / exception approval→ Nonaktif
Rekomendasi kebijakan: default-nya proses keluar diblokir bila aset aktif masih ada. Superadmin/HR tertentu dapat memakai exception dengan alasan wajib, dan exception tersebut dicatat di audit log.

Indeks minimum

UNIQUE (asset_code) UNIQUE (serial_number) — hanya bila terisi INDEX (current_branch_id, status) INDEX (owning_branch_id, status) INDEX (category_id, status) INDEX (department_id, status) INDEX (warranty_expires_at) INDEX (next_maintenance_at) INDEX asset_assignments (asset_id, returned_at) INDEX asset_assignments (employee_id, returned_at) INDEX asset_transactions (asset_id, occurred_at)
Migration dibuat baru dan reversible. Migration yang sudah pernah dijalankan di production tidak diubah.
Portabilitas database: jangan mengandalkan partial unique index untuk menjamin satu assignment aktif. SQLite dan MySQL memiliki perilaku NULL/index yang berbeda. Jaminan utama adalah transaction, lockForUpdate(), pemeriksaan assignment terbuka, dan automated invariant test.
09 · Aturan

Business Rules dan Invariant

#AturanPenegakan
BR-01Kode aset selalu unik dan tidak berubah setelah aktivasi.Unique index + validation.
BR-02Satu aset maksimal satu assignment aktif.Transaction, row lock, query invariant.
BR-03Aset assigned wajib memiliki assignment aktif.Domain Action + consistency test.
BR-04Aset maintenance/lost/retired/disposed tidak dapat di-assign.State transition guard.
BR-05Karyawan nonaktif tidak dapat menerima aset baru.Assignment request + Action guard.
BR-06Return menutup assignment; tidak menghapus histori.Update returned_at + transaction event.
BR-07Transfer merupakan satu transaksi atomik.DB transaction.
BR-08Aset dengan histori tidak dapat hard delete.Deletion blocker; gunakan retired/disposed.
BR-09Scope diberlakukan pada list, detail, mutation, download, dan export.AssetScope + Policy/authorization.
BR-10Dokumen tidak memiliki public URL.Private disk + authorized controller.
BR-11Disposal dibuat dan disetujui oleh pihak berbeda.Permission terpisah + SoD check.
BR-12Stock opname tidak langsung menimpa master.Review/reconciliation workflow.

Contoh transition guard

assignedavailableAssignment aktif ditutup dan kondisi layak
assignedmaintenanceAssignment ditutup atau replacement policy ditentukan
maintenanceavailableMaintenance selesai dan inspeksi lulus

Model relationships

Asset belongsTo Category/Branch/Department/Creator; hasMany Assignments/Transactions/Maintenances/Documents; hasOne currentAssignment menggunakan constraint returned_at IS NULL. Semua relationship memakai return type dan index yang sesuai.

Query pattern

Asset::query() ->select(/* kolom list */) ->visibleTo($user) ->matchingFilters($filters) ->with(['category:id,name', 'branch:id,name', 'currentAssignment.employee:id,full_name']) ->withCount(['maintenances', 'documents']) ->latest('id') ->paginate($perPage);
Tujuan arsitektur ini adalah menjaga controller tetap tipis dan memastikan business rule yang sama dipakai oleh UI, import, maupun proses terjadwal.

20 · Decisions

Keputusan Bisnis yang Harus Dikonfirmasi

#PertanyaanRekomendasi default
1Siapa pemilik aset: cabang, divisi, atau keduanya?Cabang wajib, divisi opsional.
2Apakah employee wajib mengakui serah-terima?Ya untuk kategori bernilai tinggi.
3Apakah offboarding diblokir bila aset belum kembali?Ya; exception khusus dengan alasan dan audit.
4Format kode aset otomatis atau manual?Otomatis dari prefix kategori + tahun + sequence.
5Apakah serial number wajib?Diatur per kategori.
6Siapa yang boleh transfer antar cabang?Asset Admin pusat atau permission khusus.
7Siapa approver disposal?Role terpisah dari requester; dapat berjenjang berdasar nilai.
8Apakah nilai perolehan boleh dilihat semua officer?Permission/report terpisah bila sensitif.
9Aset apa yang masuk pilot?Laptop, monitor, dan telepon.
